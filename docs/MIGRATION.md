# Перенос существующих сервисов под vpnstack

Если сервисы уже стоят на сервере (вручную, официальными скриптами, в Docker, через 3x-ui/x-ui или приложение
AmneziaVPN), vpnstack может их найти, считать настройки и пользователей и перезапустить под своим управлением
**с теми же портами, ключами, паролями, UUID и секретами** — ссылки и конфиги у клиентов менять не нужно.

```bash
sudo vpnstack adopt scan            # что найдено (только чтение)
sudo vpnstack adopt import all      # считать в состояние vpnstack; старые продолжают работать
sudo vpnstack adopt migrate all     # переключение (покажет план и спросит подтверждение)
sudo vpnstack adopt status          # что перенесено, где резервные копии
sudo vpnstack adopt rollback [svc]  # вернуть старую установку
sudo vpnstack adopt cleanup [svc]   # удалить остановленные старые установки (после этого отката нет)
```

То же — в меню (`vpnstack` → «Перенос существующих сервисов») и в панели (вкладка «Перенос»).

## Как проходит перенос

1. **Подготовка (без простоя).** Резервная копия конфигов старой установки в `/var/lib/vpnstack/adopt/<svc>-<время>/`,
   копирование сертификатов (Hysteria ACME/certmagic, сертификаты старого Caddy) в хранилище Caddy vpnstack,
   скачивание всех программ заранее (`Prefetch`).
2. **Переключение.** Старые юниты отключаются (`systemctl disable --now`), контейнеры останавливаются
   (`docker update --restart=no` + `docker stop`), затем vpnstack запускает свои сервисы с прежними ключами.
   Обычно простой **5–20 секунд**: клиенты один раз переподключаются.
3. **Проверка.** Юниты должны работать, нужные порты — слушаться (до 40 с). Если нет — **автоматический откат**:
   сервисы vpnstack останавливаются, старые установки запускаются как были (`--no-rollback` отключает).

Старые установки не удаляются до `adopt cleanup`: контейнеры удаляются, юниты маскируются, резервная копия остаётся.

## Что сохраняется

| Сервис | Откуда | Сохраняется |
|---|---|---|
| Hysteria 2 | systemd/скрипт get.hy2.sh, Docker | порт, сертификат (ACME — копируется; самоподписанный — тот же файл, pinSHA256 не меняется), obfs salamander/gecko и пароль, `password` (как пользователь `legacy`) и `userpass` (логины/пароли), bandwidth |
| Xray VLESS+REALITY | systemd, Docker, 3x-ui/x-ui | privateKey, serverNames, shortIds, target, UUID и flow каждого клиента, транспорт (xhttp/grpc и др. как есть), mldsa65Seed, VLESS Encryption, порт |
| telemt | systemd, Docker | секреты пользователей, tls_domain, ad_tag, middle proxy, квоты/лимиты `[access.user_*]`, порт |
| mtg | systemd, Docker | секрет fake-TLS (ключ + домен) → telemt с тем же секретом; ссылка `tg://proxy` не меняется |
| AmneziaWG | `awg-quick@*`, Docker Amnezia (`amnezia-awg*`) | ключ сервера, подсеть и адрес, порт, все параметры обфускации (Jc…H4, S3/S4, I1–I5, AWG 3.x), пиры (ключи, PSK, AllowedIPs), имена из clientsTable; версия протокола не меняется |
| FPTN | Docker | данные `/etc/fptn` (ключи, `users.list`), порт, SNI-список, фильтры, версия образа |
| TG WEB proxy | официальный `tproxy-server` | остаётся на месте; vpnstack берёт на себя Caddy (сертификаты копируются), base_path и секрет не меняются |

**Порты.** Если старый TCP-сервис слушал не 443 (например, Xray на 8443), vpnstack ставит его за общий вход 443
и добавляет перенаправление старого порта (`legacy_tcp`, nftables `redirect`) — старые ссылки с портом 8443 работают,
новые выдаются с 443. UDP-сервисы (Hysteria, AWG) остаются на своих портах.

## Ограничения

* **x-ui/3x-ui**: переносится только inbound VLESS+REALITY; остальные inbound'ы перестанут работать
  (сканер перечислит их, перенос — только с `--force`). Панель x-ui останавливается.
* **AmneziaVPN (приложение)**: после переноса сервер больше не управляется из приложения; клиенты работают.
  Для перенесённых пользователей AWG/FPTN без закрытых ключей/токенов vpnstack не может выдать конфиг заново —
  у клиентов остаются их старые конфиги, новые пользователи получают конфиги из vpnstack.
* **Hysteria**: `acl`/`outbounds` (маршрутизация) не переносятся — только с `--force`; `auth: http/command` не переносится.
* **FPTN**: за общим входом FPTN различается по SNI; если в старой установке `ALLOWED_SNI_LIST` пуст, задайте список.
* **Caddy с чужими сайтами**: сайты из `/etc/caddy/Caddyfile`, кроме перенимаемых, нужно перенести вручную:
  `vpnstack route add site.example.com 127.0.0.1:8080` (TLS на backend) или положить статику в `/var/lib/vpnstack/site`.
* Один экземпляр каждого сервиса: при нескольких найденных установках лишние нужно остановить.

## Посторонние сайты за общим входом

```bash
sudo vpnstack route add site.example.com,www.site.example.com 127.0.0.1:8443 [--proxy-protocol] [заметка]
sudo vpnstack route list
sudo vpnstack route del 1
```

TLS не расшифровывается: соединение с нужным SNI целиком передаётся на backend.
